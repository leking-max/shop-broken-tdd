# ТЗ: расчёт суммы заказа

Всё, что ниже, — источник истины для функции `calculate_order_total` из
`src/shop/checkout.py`. Константы в модуле менять нельзя, тесты на них опираются.

## 1. Деньги

* 1 рубль = 100 копеек. Любая сумма — целое число копеек.
* Дробные числа (`float`) в расчётах запрещены: 0.1 + 0.2 != 0.3.
* Проценты считаются целочисленно, округление — «половину вверх»:
  `процент от суммы = (сумма * процент + 50) // 100`.
  Готовый помощник — `shop.money.percent_of`.

## 2. Входные данные

`lines` — список словарей. Ключи словаря и их тип:

| ключ                 | тип   | смысл                                    |
| -------------------- | ----- | ---------------------------------------- |
| `sku`                | `str` | артикул, непустая строка                 |
| `qty`                | `str` | количество единиц, целое число > 0       |
| `unit_price_kopecks` | `str` | цена за единицу, целое число >= 0        |

Значения — **строки**, потому что приходят из складской выгрузки. Числом считается
значение, которое разбирает `int()`. Лишние ключи не запрещены и игнорируются.

* `promo_code` — строка; пустая строка означает «промокода нет».
* `shipping_city` — строка; пустая строка означает самовывоз, доставка не начисляется.
  Непустой город должен входить в `SUPPORTED_CITIES`.

## 3. `validate_order(lines, promo_code, shipping_city) -> str | None`

Возвращает **текст причины**, если заказ отклонён, и `None`, если заказ корректен.
Текст причины — любой непустой читаемый текст: тесты проверяют только сам факт отказа
и непустоту строки, поэтому выдумывать точную формулировку не нужно.

| №  | Условие                            | Когда отклонять                                        |
| -- | ---------------------------------- | ------------------------------------------------------ |
| 1  | нет позиций                        | `lines` пустой                                           |
| 2  | пустой `sku`                       | артикул не может быть пустым                            |
| 3  | нет ключа из `REQUIRED_LINE_KEYS`  | в позиции с номером N отсутствует ключ                   |
| 4  | `qty` не число                     | `int()` не разбирает значение                            |
| 5  | `qty <= 0`                         | количество должно быть больше нуля                      |
| 6  | `unit_price_kopecks` не число      | `int()` не разбирает значение                            |
| 7  | `unit_price_kopecks < 0`           | цена не может быть отрицательной                        |
| 8  | дважды один `sku`                  | артикул не может повторяться                            |
| 9  | `promo_code` не пустой и неизвестен | такого промокода нет в `PROMO_CODES`                     |
| 10 | город не пустой и не поддерживается | такого города нет в `SUPPORTED_CITIES`                  |

Номер позиции N нумерация с 1.

## 4. `calculate_order_total(lines, promo_code, shipping_city) -> int | None`

Если заказ отклонён, функция возвращает `None`. Иначе — сумму заказа в копейках.
Порядок шагов строго такой:

1. `subtotal` = сумма `qty * unit_price_kopecks` по всем позициям.
2. Ярусная скидка: берём порог из `TIER_DISCOUNTS`, для которого выполняется
   `количество единиц >= порог`, где количество единиц — сумма `qty` по позициям.
   Подходит только один порог — наибольший подходящий.
3. Промокод даёт процент из `PROMO_CODES` (0, если промокода нет).
4. Из ярусной скидки и промокода выбирается **больший** процент. Они не суммируются.
5. Процент ограничен сверху: `MAX_DISCOUNT_PERCENT`.
   `discount = percent_of(subtotal, discount_percent)`.
6. `discounted_subtotal = subtotal - discount`.
7. Доставка: `SHIPPING_KOPEKS`, если город непустой **и**
   `discounted_subtotal < FREE_DELIVERY_FROM_KOPEKS`, иначе `0`.
8. `base = discounted_subtotal + доставка`.
9. `vat = percent_of(base, VAT_PERCENT)`.
10. `total = base + vat`.

## 5. Примеры расчёта

Все числа — копейки. Проверьте примеры тестами: они должны пройти.

| шаг                | Пример 1 | Пример 2 | Пример 3 | Пример 4 |
| ------------------ | -------- | -------- | -------- | -------- |
| позиции            | 1 × 10 000 | 10 × 1 990 | 50 × 1 990 | 100 × 10 000 |
| промокод / город   | нет / самовывоз | нет / самовывоз | `WELCOME10` / `msk` | `VIP35` / `spb` |
| `subtotal`         | 10 000   | 19 900   | 99 500   | 1 000 000 |
| ярусная скидка     | 0 %      | 5 %      | 15 %     | 15 %     |
| промокод           | 0 %      | 0 %      | 10 %     | 35 %     |
| итоговый процент   | 0 %      | 5 %      | 15 %     | 30 % (потолок) |
| `discount`         | 0        | 995      | 14 925   | 300 000  |
| `discounted_subtotal` | 10 000 | 18 905   | 84 575   | 700 000  |
| доставка           | 0        | 0        | 49 000   | 0        |
| `base`             | 10 000   | 18 905   | 133 575  | 700 000  |
| `vat` (20 %)       | 2 000    | 3 781    | 26 715   | 140 000  |
| **`total`**        | **12 000** | **22 686** | **160 290** | **840 000** |

Граница бесплатной доставки (пример 5, без скидок):

| позиции | промокод / город | `subtotal` | доставка | `base`  | `vat`  | `total`  |
| ------- | ----------------- | ---------- | -------- | ------- | ------ | -------- |
| 1 × 499 999 | нет / `msk`  | 499 999 | 49 000 | 548 999 | 109 800 | 658 799 |
| 1 × 500 000 | нет / `msk`  | 500 000 | 0       | 500 000 | 100 000 | 600 000 |

Ровно на пороге доставка уже бесплатна: сравнение строгое `<`.

## 6. Чего делать нельзя

* Менять сигнатуры, константы и имя файла.
* Менять уже написанные тесты, ослаблять их или помечать `skip` / `xfail`.
* Добавлять зависимости и создавать классы (проект их не использует).
