# Часть 1. Починка красного CI

## Задача

Сборка репозитория красная с самого начала — так задумано. Задача части 1:
сделать её зелёной.

## Что проверяет сборка

| Джоба          | Что проверяет                        | Инструмент                |
| -------------- | ------------------------------------ | ------------------------- |
| `format`       | единый вид кода                      | `ruff format --check`     |
| `lint`         | вероятные ошибки                     | `ruff check`              |
| `types`        | соответствие аннотациям              | `mypy src tests` (strict) |
| `tests`        | поведение кода части 1               | `pytest`                  |
| `tests` (3.13) | то же самое на второй версии Python | `pytest`                  |

Каждая джоба падает по своей причине, и у каждой свой инструмент.

## Как проверять

```bash
./scripts/check-part1.sh
```

Скрипт запускает ровно те же команды, что и пайплайн, и печатает сводку в конце.
Полный набор проверок, включая ещё не сделанную часть 2, запускает
`./scripts/check.sh`.

Что делает каждый инструмент и как читать его вывод — в
[01-toolchain.md](01-toolchain.md).

## Границы задачи

Нельзя:

* менять содержимое `tests/` — ни строки;
* «лечить» красное ослаблением проверок: удалять `assert`, ставить `skip` или
  `xfail`, добавлять `# noqa` и `# type: ignore`, отключать правила в
  `pyproject.toml`;
* удалять джобы из `.github/workflows/`.

Можно править код и конфигурацию — всё, что не ослабляет проверки.

## Что должно получиться

`./scripts/check-part1.sh` — все проверки зелёные, и джобы `part1-ci.yml` в
GitHub Actions тоже зелёные.
